# Comments Loop — Carrot Broadcast

Скрипт из двух частей:

1. **Чередование комментариев** — два текстовых слоя **Comment 1** / **Comment 2**
   по очереди появляются/исчезают, строки берутся из слоя **MainText**.
2. **Раскладка** — строки из `MainText` кладутся в `Line1/Line2` прекомпа
   `LINES`, ширина подложки `Plaska` подгоняется под текст, строка `Time`
   раскладывается по `Hours/Minutes`, а прекомп `LINES` сдвигается по вертикали.

Файл [`comments-loop.js`](./comments-loop.js) разбит на три блока-заготовки.
Скопируй каждый блок в соответствующее поле Carrot:

| Поле Carrot   | Блок в файле                        |
| ------------- | ----------------------------------- |
| **Startup**   | всё от `// STARTUP` до `// SETSTATE` (константы + функции) |
| **SetState**  | блок `if (statename == "LOOP") { initLoop(); }` |
| **ProcessFrame** | блок от `if (statename != "LOOP") ...` до `updateLayout();` |

## Структура функций

`Startup` содержит только объявления и функции, вся работа — в `ProcessFrame`:

- `updateComments()` — смена текста скрытых комментариев по расписанию (только в LOOP);
- `updateLayout()` — раскладка кадра, вызывает:
  - `parseLines()` — разбор `MainText` (лишние строки сверх `MAX_LINES` сливаются в последнюю);
  - `fillSlots()` — заполнение `Line1/Line2` + замер самой длинной строки;
  - `fitPlaska()` — подгон ширины подложки под текст;
  - `updateTime()` — раскладка `Time` по `Hours/Minutes` + сдвиг `Dots/Minutes`;
  - `placeLines()` — вертикальный сдвиг прекомпа `LINES`.

## Тайминги

Заданы вверху `Startup`:

```js
var START_TIME  = 0.18;   // первое появление Comment 1
var PERIOD      = 5.98;   // период чередования (появление -> появление)
var GAP         = 0.2;    // пауза между исчезновением одного и появлением другого
var CHANGE_LEAD = (PERIOD + GAP) / 2;   // 3.09 — за сколько до появления меняем текст
```

Появления: `T_k = START_TIME + k * PERIOD` → `0.18, 6.16, 12.14, 18.12, ...`
(слот чётный → Comment 1, нечётный → Comment 2).

## Почему нет рассинхрона

Плашка скрыта примерно `PERIOD + GAP ≈ 6.18` c между двумя своими показами.
Текст меняем в **середине** этого окна (`CHANGE_LEAD ≈ 3.09` c до появления):

```
исчезла            меняем текст            появилась снова
  |------- 3.09 c -----|------- 3.09 c -------|
```

Запас ~3 c с обеих сторон означает, что даже заметный дрейф анимации за
60-секундный LOOP не приведёт ни к опозданию текста, ни к миганию.
`nextChangeTime` каждый раз считается по формуле от `START_TIME`
(`START_TIME + nextSlot*PERIOD - CHANGE_LEAD`), а не накапливается —
поэтому ошибка не растёт от цикла к циклу.

## Логика подстановки строк

- Comment 1 показывает строки `0, 2, 4, ...`, Comment 2 — `1, 3, 5, ...`.
- На экране строки идут последовательно `0, 1, 2, 3, ...` и зацикливаются.

За 60 c LOOP помещается ~10 появлений (`60 / 5.98`). При зацикливании
композиции счёт строк начинается заново с 0 и 1.

Особые случаи:
- **пустой MainText** — оба слоя скрываются (`Enabled = false`);
- **одна строка** — обе плашки показывают её же.

## Раскладка (константы вверху `Startup`)

```js
var MAX_LINES = 2;                 // максимум строк (лишние сливаются в последнюю)
var SHIFT_1 = 17, SHIFT_N = 12;    // сдвиг строк по вертикали
var BASE_X = 960, BASE_Y = 540;    // базовая позиция прекомпа LINES
var BG_PAD = 30;                   // отступ подложки по бокам от текста (px)
var PLASKA_UNIT_TO_PX = 1024;      // перевод единиц ширины солида в пиксели
```

При чистке убраны: отладочные `writeLn(...)` и мёртвый код (`scalePctPx`/`MAX_PX`
считались, но нигде не применялись). Если нужен автоподгон масштаба самого
текста при превышении ширины — скажи, верну как рабочую функцию.

Замер ширины `Hours` в `updateTime()` оставлен как в исходнике — по текущему
(ещё не обновлённому) тексту. В установившемся режиме это не влияет; если время
меняется рывком, можно перенести замер после установки текста.

## Утилита `fitTextWidth`

Отдельный сниппет [`fit-text-width.js`](./fit-text-width.js) — подгонка
масштаба текста под максимальную ширину. Уменьшает масштаб слоя, только если
текст шире `maxWidth`, иначе возвращает 100%. Мерит натуральную ширину,
поэтому её можно звать каждый кадр.

```js
fitTextWidth(preComp.layer("Line1"), 1000);
```

Если scale задаётся присваиванием, поменяй последнюю строку функции на
`layer.transform.scale = [pct, pct, 100];`.

Например, в `fillSlots()` после установки текста строки:

```js
l.TextSource.Text = i < lines.length ? lines[i] : "";
fitTextWidth(l, MAX_PX);   // где MAX_PX — нужная максимальная ширина
```

## Утилита `splitTextToLayers`

Сниппет [`split-text.js`](./split-text.js) — разбивка текста одного слоя по
строкам в другие слои. Режет текст `src` на непустые строки и раскладывает
их по одной в слои массива `targets` (лишние слои очищаются).

```js
splitTextToLayers(
    thisComp.layer("MainText"),
    [thisComp.layer("Line1"), thisComp.layer("Line2")]
);
```

## Движение текста за null'ом (`name-follow.js`)

Сниппет [`name-follow.js`](./name-follow.js) — текст `Name` едет за `Null 2`,
проходя путь, зависящий от своей ширины (шире текст → длиннее путь).

Модель подтверждена двумя замерами (`466 → 2.35`, `761.3 → 1.73`). Так как
делится абсолютная позиция, определяющая величина — конечная позиция текста
`NULL_END / C`; она растёт ровно на ширину текста, поэтому:

\[ C(width) = \frac{NULL\_END}{width + K} = \frac{1913}{width + 346} \]

где `K ≈ 346` откалибровано по обеим точкам (`1913/2.35 − 466 ≈ 348`,
`1913/1.73 − 761.3 ≈ 344.5`).

```js
function speedCoeff(width) { return 1913 / (width + 346); }

function setEndPos() {
    var width = thisComp.layer("Name").sourceRectAtTime(false).width;
    thisComp.layer("Name").transform.position.x =
        thisComp.layer("Null 2").transform.position.x / speedCoeff(width);
}
```

## Покраска текста (`highlight-color.js`)

Сниппет [`highlight-color.js`](./highlight-color.js) красит текст:

- если `*` нет — весь текст **зелёный**;
- если `*` есть — помеченные слова **зелёные**, остальное **белое**.

Особенности:
- richtext-движок заменяет переносы на `<div>…</div>` — скрипт возвращает
  обычные переносы (`<div>` → `\n`, `</div>` убирается, `<br>` → `\n`);
- красит **построчно**, чтобы `<font>` не пересекал переносы (иначе при обратной
  разбивке на `<div>` получается битая разметка);
- в строке с `*` слова красятся вложенным `<font>` (зелёный внутри белого),
  теги закрываются корректно;
- идемпотентно: уже покрашенный текст без `*` повторно не трогается.

Цвета задаются константами `GREEN` / `WHITE`. Если движок не рендерит вложенные
`<font>`, вернись к предыдущей версии с посегментной покраской (см. историю git).

## Растяжка подложки (`fit-plaska.js`)

Сниппет [`fit-plaska.js`](./fit-plaska.js) —
`fitPlaska(textLayer, plaska, plaskaWidthPx, pad)` растягивает solid-подложку по
ширине текста, меняя только `scale.x`.

```js
fitPlaska(thisComp.layer("Name"), thisComp.layer("Plaska"), 1920, 30);
```

Ширина солида передаётся числом (`plaskaWidthPx`), потому что в движке
`plaska.width` / `plaska.source.width` недоступны, а `sourceRectAtTime()` у
солида возвращает ширину не в пикселях. `plaskaWidthPx` — реальный размер солида
в px при `scale.x = 100` (из его настроек). Формула:
`scale.x = (ширина_текста + 2·pad) / plaskaWidthPx · 100`.

## Подчёркивание текста (`underline-line.js`)

По итогам изучения документации Carrot: **подчёркивания средствами текста нет**.

- Тип `RichText` поддерживает только `<font color="…">` (руководство «Работа со сторонним ПО»).
- В объектной модели у текста есть только `text.sourceText` (`scripting/reference-guide.md`).
- `<u>`, `text-decoration` и combining-символ `U+0332` движок не рендерит (проверено).

Поэтому подчёркивание рисуется **отдельным слоем-линией (solid)** под текстом —
приём согласован с базой знаний Carrot («солид под размер текста»). Сниппет
[`underline-line.js`](./underline-line.js):

- `underlineLayer(textLayer, line, lineWidthPx, yOffset)` — подчёркивает **весь**
  текстовый слой (линия по всей ширине текста);
- `underlineWordInline(textLayer, line, lineWidthPx, wordRegex, yOffset)` —
  подчёркивает **отдельное слово** внутри одной строки, **без дробления текста
  на слои**: положение слова вычисляется временным замером «префикса» и
  «префикс+слово» через `sourceRectAtTime` (в том же кадре, с возвратом текста).
  Надёжно для одностройного текста с выравниванием по левому краю; для
  многострочного/центрированного — X слова так точно не получить.

Есть и вариант без скрипта — выражением на `Scale` линии (внизу файла).

## Бегущая строка с подложкой (`ticker.js`)

Файл [`ticker.js`](./ticker.js) — полный скрипт бегущей строки **для проекта без
медиа-разделителей и цветовых слоёв**, где все слои строки лежат в
**прекомпозиции**. Структура:

- **главная композиция** (`thisComp`): слой-источник строк `inputext`;
- **прекомп `linesPreComp`**: тексты `myText 1 … myText 12`, подложки
  `dark_green_line N`, управляющий null `master` (тексты и подложки привязаны
  к `master` внутри прекомпа).

К слоям прекомпа скрипт обращается через `app.project.item("linesPreComp")`
(как в `comments-loop.js`), а не `thisComp.layer(...)`. Имена прекомпа и
источника задаются вверху (`LINES_COMP_NAME`, `SOURCE_LAYER`). Разбит
маркерами `// STARTUP` / `// SETSTATE` / `// PROCESSFRAME`.

Зелёная подложка (`dark_green_line`) стоит под **каждым** текстом, номер
совпадает (1:1):

```
myText 1 -> dark_green_line 1
myText 2 -> dark_green_line 2
myText 3 -> dark_green_line 3
...        (myText N -> dark_green_line N)
```

Подложка:

- растягивается по ширине текста + **26px** с каждой стороны (`PLATE_PAD`);
- ставится по центру текста и едет вместе с ним (обновляется в `ticker("init")`
  и при переносе элемента в хвост — блок `frame % 17`, каждый кадр не нужно,
  т.к. подложка привязана к `master`).

Что настроить в композиции:

1. тексты и подложки **привязать к `master`** (parent) — всё внутри `linesPreComp`;
2. якорь подложки — по **центру** (ровные отступы, симметричный рост);
3. `PLATE_BASE_PX` — реальная ширина солида в px при `scale.x = 100`
   (сейчас заглушка `400`, подставь своё);
4. подложку положить **ниже своего текста** в стеке слоёв прекомпа.

Необязательные слои (`TTL`) читаются, только если существуют; из исходника
убраны media/separator (`getMediaWidth`, `sepWidth`, `Footages`) и цветовые
слои (`color_text`, `color_line`, `Gray_String`/`Tint`, `Fill`). Порядок слоёв
берётся строго по номерам `myText 1..N`, а не по расположению в панели.
`region_start`/`region_end` — в координатах прекомпа.

Универсальный вариант той же идеи (одна функция, без привязки к структуре
тикера) — [`ticker-plate.js`](./ticker-plate.js), см. ниже.

## Подложка бегущей строки (`ticker-plate.js`)

Сниппет [`ticker-plate.js`](./ticker-plate.js) —
`fitTickerPlate(text, plate, plateWidthPx, pad)` — зелёный солид под текстом
бегущей строки. В отличие от `fitPlaska` (та меняет только `scale.x`), здесь
строка **едет**, поэтому подложка каждый кадр и растягивается по ширине текста
+ отступы (по умолчанию **26px** с каждой стороны), и держится **по X** под
своим текстом.

```js
fitTickerPlate(thisComp.layer("Text 2"), thisComp.layer("Plate 2"), 400, 26);
```

Требования: якорь солида — по **центру** (симметричный рост + ровные отступы);
`plateWidthPx` — реальная ширина солида в px при `scale.x = 100`. Звать нужно
там же, где двигаются слои строки (внутри `ticker_anim` / в `ProcessFrame` после
пересчёта позиций). По вертикали Y не трогается — задай его в слое один раз
(или включи блок `ALSO_Y` в файле). Для нескольких пар текст+подложка — цикл по
массиву пар (пример в файле).

## Центрирование строки слоёв (`center-row.js`)

Сниппет [`center-row.js`](./center-row.js) — `centerRowX(layers, centerX, gap)`
держит несколько текстовых слоёв (напр. Дата + Время) как единую группу,
отцентрованную по X-координате, независимо от их ширины. Складывает видимые
ширины (`sourceRectAtTime`) и зазоры, находит левый край группы от центра и
раскладывает слои слева направо.

```js
centerRowX([thisComp.layer("Date"), thisComp.layer("Time")], 1117, 20);
```
