# Carrot Ticker REST Client

Клиент для **двух задач** бегущей строки, без открытия интерфейса Carrot:

1. менять строки на лету (`list` / `add` / `rm` / `clear`);
2. выдавать и снимать строку с эфира (`air-on` / `air-off`).

Без внешних зависимостей. Нужен **Node.js >= 18**.

Это **не** скрипт шаблона. Скрипт шаблона (`../ticker.js`) копируется в поля
Startup / SetState / ProcessFrame внутри Carrot. Этот каталог — отдельная
программа, которую запускаешь на компьютере с доступом к Carrot Server.

---

## 0. Что должно быть уже готово в Carrot

Клиент **не создаёт** шаблон и плейлист. Он работает с тем, что уже есть:

1. Шаблон бегущей строки с скриптом `ticker.js` и текстовой переменной
   (обычно `inputext`) — источником строк.
2. **Событие**, созданное из этого шаблона.
3. Событие стоит в **плейлисте** как элемент сценария (item). Без элемента
   строки менять ещё можно, а в эфир выдавать — нет: Carrot проигрывает
   именно элемент, не событие.
4. Запущены **Carrot Server** и **Carrot Engine** (для эфира).
5. Чтобы менять строки, **пока графика уже в эфире**, у события должен быть
   включён `allowRuntimeChange`.

## 1. Установка на компьютере, с которого будешь управлять

Нужен Node.js 18+ (`node -v`). Затем:

```bash
cd carrot/rest-client
cp .env.example .env
```

Открой `.env` и заполни как минимум:

```
CARROT_BASE_URL=http://АДРЕС-СЕРВЕРА:ПОРТ/api
CARROT_LOGIN=твой_логин
CARROT_PASSWORD=твой_пароль
```

Порт REST в PDF не указан — это адрес, по которому у вас поднят REST API
Carrot (часто тот же хост, что Carrot Server, но **не** WebSocket-порты
24710/24712). Если не знаешь URL — спроси у того, кто ставил сервер.

Проверка, что сервер отвечает:

```bash
node cli.js events
```

Должен появиться список событий (`id` и имя). Если 401 — неверный логин/пароль.
Если не коннектится — неверный `CARROT_BASE_URL`.

## 2. Привязать клиент к своей бегущей строке

### Строки (событие + переменная)

```bash
node cli.js events                  # найти имя/id события бегущей строки
node cli.js vars --event-name "ИМЯ" # посмотреть переменные
```

В `.env` пропиши **одно** из:

- `CARROT_EVENT_NAME=ИмяСобытия`  (удобнее)
- `CARROT_EVENT_ID=guid-события`  (точнее, если имён несколько)

И имя переменной, если оно не `inputext`:

```
CARROT_TICKER_VAR=inputext
```

В `vars` должно быть видно поле с типом `Text` / `RichText` и многострочным
значением — это и есть источник строк для скрипта шаблона.

Проверка:

```bash
node cli.js list
```

### Эфир (элемент сценария)

Для `air-on` / `air-off` нужен **элемент**, не событие. Два способа:

**A. Знаешь id элемента** — пропиши `CARROT_ITEM_ID=...` и всё.

**B. Не знаешь** — найди плейлист и элемент:

```bash
node cli.js playlists
node cli.js find-item --playlist GUID_ПЛЕЙЛИСТА --event-name "ИМЯ"
```

В `.env`:

```
CARROT_PLAYLIST_ID=guid-плейлиста
```

Клиент сам найдёт в плейлисте элемент, который ссылается на твоё событие.
Найденный id лучше один раз прописать в `CARROT_ITEM_ID`, чтобы не искать
каждый раз.

## 3. Повседневная работа

Все команды ниже запускаются из `carrot/rest-client` (после заполненного `.env`).

### Строки

```bash
node cli.js list                         # текущие строки с индексами
node cli.js add "Срочная новость: ..."   # в конец
node cli.js add "Молния!" --at 0         # в начало (позиция 0)
node cli.js rm 2                         # удалить строку с индексом 2
node cli.js rm --match "устарело"        # удалить все, где есть подстрока
node cli.js set-file lines.txt           # заменить всё содержимым файла
node cli.js clear                        # очистить
```

`--at` у команды `add` — это **позиция строки**, не время эфира.

Новые строки попадут в переменную события сразу. Скрипт шаблона подхватит
их на следующем `init` / цикле бегущей строки (когда элемент переносится
в хвост или при следующем входе в IN). Это не мгновенная подмена уже
едущего куска ленты.

### Эфир

Обычный цикл:

```bash
node cli.js status     # Unloaded / Loading / Ready / Active
node cli.js air-on     # прогрузить (если надо) → дождаться Ready → выдать
node cli.js air-off    # снять (Closing State / OUT)
node cli.js unload     # выгрузить из памяти, когда строка больше не нужна
```

Тонкие команды, если хочешь управлять шагами сам:

```bash
node cli.js load                 # только прогрузить
node cli.js in                   # выдать (элемент уже должен быть Ready)
node cli.js out                  # снять
node cli.js in --at 2026-09-10T12:00:00Z --duration 3600
node cli.js out --at 2026-09-10T12:05:00Z
```

`--at` у `in` / `out` / `air-on` / `air-off` — это **UTC-время** выдачи/снятия.
`--duration` — длительность в **кадрах**. Без флагов — сразу, как дойдёт команда.

Типичные ошибки эфира:

| Сообщение        | Что не так                                      |
| ---------------- | ----------------------------------------------- |
| `InvalidState`   | `in` до `load`, или `unload` пока элемент Active |
| `NoEngines`      | Engine не запущен / нет схемы проигрывания      |
| `NotFound`       | неверный item/event id                          |
| `InUse`          | объект занят (нельзя удалять активное)          |

## 4. Что за файлы и какие трогать

| Файл                 | Нужен тебе? | Зачем                                        |
| -------------------- | ----------- | -------------------------------------------- |
| `cli.js`             | да          | запускаешь команды (`node cli.js ...`)       |
| `.env`               | да          | **создаёшь сам** из `.env.example`, секреты  |
| `.env.example`       | как образец | в git, без паролей                           |
| `carrot-client.js`   | нет         | ядро REST (логин, запросы)                   |
| `ticker.js`          | нет         | логика строк                                 |
| `playout.js`         | нет         | логика эфира                                 |
| `package.json`       | нет         | описание пакета, зависимостей нет            |
| `README.md`          | справка     | эта инструкция                               |

В шаблон Carrot по-прежнему копируется **`../ticker.js`**, не эти файлы.

Как библиотека в своём скрипте:

```js
const { CarrotClient } = require('./carrot-client');
const { TickerClient } = require('./ticker');
const { PlayoutClient } = require('./playout');
```

## Как это устроено внутри

**Строки:** `GET /events/{id}` → переменная `inputext` → `split` по `\n` →
правка → `PATCH /events/{id}/editVariables`.

**Эфир:** `POST /items/{itemId}/load` → `takeIn` → `takeOut` → `unload`.
Статусы: Unloaded 0 → Loading 1 → Ready 2 → Active 3.

Авторизация: `POST /auth/generate` (JWT, ~1 час). Клиент обновляет токен сам.
Каждый запрос несёт обязательный конверт `MessageId/Time/SenderId/ReceiverId`.
