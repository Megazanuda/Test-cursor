# Carrot Ticker REST Client

Небольшой REST-клиент для Carrot Broadcast, чтобы **на лету добавлять и убирать
строки бегущей строки**, не открывая интерфейс Carrot.

Строки бегущей строки хранятся в одной многострочной текстовой переменной
события (по умолчанию `inputext`) — той самой, что читает скрипт шаблона
(`ticker.js`, `split` по переводам строк). Клиент читает текущее значение,
меняет набор строк и пишет обратно через `PATCH /events/{eventId}/editVariables`.

Без внешних зависимостей. Нужен **Node.js >= 18** (встроенный `fetch`).

## Файлы

- `carrot-client.js` — ядро REST-клиента (авторизация JWT, автообновление
  токена, обязательный конверт `MessageId/Time/SenderId/ReceiverId`, разбор
  `Message<T>` и доменных ошибок `errorCode`, ретраи на сетевых сбоях).
- `ticker.js` — операции над строками: `getLines / setLines / addLine /
  removeAt / removeMatching / clear`.
- `cli.js` — командная строка + загрузка `.env`.
- `.env.example` — шаблон конфигурации.

## Настройка

```bash
cd carrot/rest-client
cp .env.example .env
# отредактируй .env: URL, логин/пароль, событие (id или имя), имя переменной
```

Конфиг берётся из `.env` (рядом с `cli.js` или в текущей папке) или из
переменных окружения. Ключевые параметры:

| Переменная          | Назначение                                             |
| ------------------- | ------------------------------------------------------ |
| `CARROT_BASE_URL`   | базовый URL, напр. `http://host:port/api`              |
| `CARROT_LOGIN`      | логин пользователя Carrot                              |
| `CARROT_PASSWORD`   | пароль                                                 |
| `CARROT_EVENT_ID`   | id события бегущей строки (точнее всего)               |
| `CARROT_EVENT_NAME` | имя события (если не знаешь id — найдёт по имени)       |
| `CARROT_TICKER_VAR` | имя текстовой переменной, по умолчанию `inputext`      |

## Использование

```bash
# список событий (чтобы узнать id/имя бегущей строки)
node cli.js events

# показать текущие строки
node cli.js list

# добавить строку в конец
node cli.js add "Срочная новость: ..."

# добавить строку на позицию 0 (в начало)
node cli.js add "Молния!" --at 0

# удалить строку по индексу (индексы см. в `list`)
node cli.js rm 2

# удалить все строки, содержащие подстроку
node cli.js rm --match "устарело"

# заменить все строки содержимым файла (по строке на строку)
node cli.js set-file lines.txt

# очистить бегущую строку
node cli.js clear
```

Событие можно задать и флагами, не трогая `.env`:

```bash
node cli.js list --event-name "Ticker" --var inputext
node cli.js add "текст" --event 3fa85f64-5717-4562-b3fc-2c963f66afa6
```

## Как это работает (кратко)

1. `POST /auth/generate` — получаем JWT (живёт 1 час, клиент обновляет сам).
2. `GET /events` — находим событие по имени (если задан не id, а имя).
3. `GET /events/{id}` — читаем переменные, берём `inputext`, режем на строки.
4. Меняем набор строк локально (add/rm/set/clear).
5. `PATCH /events/{id}/editVariables` — пишем обратно `[{name, value}]`,
   строки склеены через `\n`.

## Замечания

- Чтобы менять переменные, пока событие **в эфире**, у события должен быть
  включён `allowRuntimeChange` (иначе Carrot вернёт ошибку). Само значение
  подхватится шаблоном на следующем `init`/цикле бегущей строки.
- Слишком длинное значение переменной вернёт `InvalidValue` (есть `lengthLimit`).
- Пустые строки игнорируются — индексация `list/add/rm` остаётся предсказуемой.
- Как библиотека: `const { CarrotClient } = require('./carrot-client');`
  и `const { TickerClient } = require('./ticker');` — можно встроить в свой сервис.
